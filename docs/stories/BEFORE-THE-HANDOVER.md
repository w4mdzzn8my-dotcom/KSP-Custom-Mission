# Before the Handover — the second count

Routine maintenance/social scene draft by Basil's Codex. This is proposed story
content, not a playable mission or an additional emergency. No emergency timing
is specified. It expands the workshop premise in issue #7.

## Setting and clue

The habitation galley, then the lab and cryobay. Hamish and Basil are awake;
Ada and Vikram remain frozen until the normal relief procedure. Nobody is a
villain and there is no failing life-support system in this scene.

The handover notes say one water allowance was issued. Basil remembers two.
The second entry in the manual notes was a reservation for the next exercise
session, copied into the consumption column. This is a bookkeeping error in
story records; the game must never silently add or remove actual Water to make
the plot fit. A measured resource total and the actual transaction ledger settle
what was consumed. Without that ledger, present this as a manual-note puzzle,
not an automatically proven resource reconciliation.

Hamish: “I don't want to wake them with a report that says 'probably enough.'”

Basil: “And I don't want to finish the report by guessing which number looks
better. One count, one measurement, then we decide.”

## Work and choices

1. In the galley, read actual Food/Water totals and separate consumed entries
   from reserved entries. Each player can recount a different column. In single
   player this is a rehearsal; two simultaneous human actions are not claimed.
2. In the lab, record the current observation state. A fitted stock experiment
   may be used if present; no fictional instrument or science points appear.
3. Choose whether to finish a bounded observation now or save its status for Ada.
   Finishing costs time and must leave a rested awake watch. Deferring preserves
   crew readiness but requires a precise handover note. Both are valid outcomes.
4. Take meals/drinks and assess fatigue through actual implemented room controls.
   Do not inject an injury to create a medical task. Existing injuries, if any,
   use the real available treatment/recovery flow.
5. Visit the cryobay and inspect actual pod/power/Glykerol state. Thaw the relief
   pair only when the qualified handover logic allows it. Verify actual pod and
   roster state before freezing the outgoing watch.
6. Save a corrected handover record: consumed/reserved distinction, observation
   state, actual supply reading, crew readiness and remaining work.

Hamish, if the observation is deferred: “Write where you stopped. Ada can finish
an honest half-page more easily than a confident blank one.”

Basil, if the observation is completed: “Then the last reading belongs in the
report. So does the time it cost us.”

Ada, after a verified thaw (dialogue only until animation/voice integration):
“Good. You left a decision I can understand, not a mystery I have to repeat.”

## Recovery and evidence

A wrong first count does not remove supplies or trigger an emergency. Repeat the
measurement and correct the note. If the crew is too tired or reserves are too
low, keep the outgoing pair awake only as supported by the actual watch rules,
resolve the ordinary need and resume; the campaign clock must continue.

Proposed active work: 10–15 minutes of recount/measurement, 5–10 minutes of lab
review and a separately qualified handover. Do not inflate this to an 80-minute
idle countdown. The full month needs other maintenance and care activities.

## Implementation dependencies

- Persisted resource transaction ledger distinguishing issuance from reservation.
- Saved observation and handover records with plan revisions and crew identities.
- Actual room/fitness gates, qualified pod power accounting and thaw verification.
- Dialogue choice persistence and later authenticated multiplayer decisions.
- Scripted Kerbal handoff animations are requested but not implemented by this
  text; player traversal or a clearly labelled text scene is the current proposal.

Acceptance requires truthful resource deltas, both recoverable outcomes, no
extra emergency, and persistence through save/reload and later two-client reconnect.
